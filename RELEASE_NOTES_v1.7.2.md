# v1.7.2 — Native Home verification candidate

- Native ABI inventory reads ARM ELF headers and, where readelf exists, dependencies, ARM attributes and symbol-version requirements. No binaries are executed or loaded by the inventory. A matching header is not ABI certification.
- Upstream lginputhook v1.5.1 service uses ezinject against multiple system processes and writes /tmp/inputhook without verifying success. The inputhookpp upstream main source supports ignoring mapped keys after invoking a command on keydown, but is not proof of the packaged binary's exact revision or compatibility. See https://github.com/Simon34545/lginputhook/tree/v1.5.1 and https://github.com/sundermann/inputhookpp (GPL-3.0; no upstream code or binaries redistributed).
- Hardware baseline: v1.7.1 had 17 key events, 14 successful bounded recoveries, 3 coalesced events, 1.6–1.7s render. Native Ribbon remains visible. Input Hook was absent on the TV. Do not reinstall/launch an incompatible injector automatically.
- Native workflow (only after independent safe Input Hook compatibility review): stop legacy observer, native-abi, native-probe, enable, native-begin, press physical Home 3 times with 5s spacing, native-check. No manual invocation during the test. Fresh trace must have three invocations and accepted launches, no observed NL_HOME_SHOWN. Log absence alone cannot prove zero flash; visually inspect and test other remote keys. Boot-arm now requires fresh proof and explicit --visual-confirm; do not reboot until safe. Upstream autostart is not controlled by this proof. Restore mapping with disable; an injected library may stay loaded until clean reboot.
- V9.1 fallback refuses known mapped hook libraries even if marker is absent at activation. Safe recovery clears fast/ribbon flags and proof. No system partition writes or bind mounts. Hardware and exact C++ binary ABI remain unverified. This is a prerelease, not a native interception implementation.
